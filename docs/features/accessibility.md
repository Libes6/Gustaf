# Accessibility

The UI is built toward WCAG 2.1 AA and checked from the code (no screen reader or axe run was possible in the dev environment):

- **Keyboard**: sidebar rows, settings navigation and list items are real buttons (the project/chat actions appear on focus as well as hover and chat rows have a "More" button next to right-click), menus (`Menu.tsx`) move focus into the menu with arrow keys, Home/End, Escape and Tab to leave, and restore focus afterwards. The model picker is a combobox with a listbox (arrows, Enter, Cmd+1..9, Ctrl/Cmd+D toggles the favorite). Dialogs (project instructions, commit, create project, compare, agent transcript, file diff, model picker) use `useDialogFocus` (`src/lib/useDialogFocus.ts`, pure parts in `dialogFocus.ts`): focus moves in, Tab stays inside, Escape closes, focus returns to the opener. The tool-approval card is an inline `alertdialog` and deliberately does not take focus, so a stray Enter while typing can never approve a command (Cmd+Enter and Esc remain global).
- **Focus visibility**: one `:focus-visible` ring in `theme.css` using `--focus`, the accent adjusted to at least 3.5:1 against the page in the current theme (`focusRingColor` in `themeUtil.ts`).
- **Semantics**: landmarks (`nav` rail, `aside` sidebar and panels, `main` chat and settings), `aria-label` on icon buttons, `aria-expanded` on disclosures, `aria-pressed` on segmented controls, `role="switch"` with labels on toggles, `role="dialog"`/`aria-modal`, `<progress>` with labels for rate limits, and `<html lang>` follows the locale. A single polite, visually hidden status region in the chat announces "Assistant is responding", "Response finished" and the retry notice; errors use `role="alert"`; the feed is `role="log"` with `aria-live="off"` so streamed tokens are not read out.
- **Contrast**: `tests/contrast.test.mjs` parses `theme.css` and requires 4.5:1 for text tokens on the main surfaces in both themes and 3:1 for the focus ring and switch track. Built-in accent presets are covered by `tests/theme.test.mjs`.
- **Motion**: `prefers-reduced-motion` turns off the shimmer, caret blink, transitions and flash highlights; spinners keep turning, slowly.
- **Target size**: small icon buttons keep their look but get a 24px hit area (`theme.css`, "accessibility" block).
- **Regression guard**: `tests/a11yLint.test.mjs` scans `src/**/*.tsx` for buttons without a name, clickable non-buttons and unlabeled form fields. Add a justified entry to its `ALLOW` map rather than weakening a rule.

Known gaps: not verified with VoiceOver or axe in the running app; native checkboxes (16px) and the custom accent color used as a text/fill color (a very light accent can be low contrast outside the focus ring) are not adjusted; drag and drop of chats into sections is mouse only (the chat menu has "Add to section" as the keyboard route); canvas artifacts and model-written Markdown are rendered as given and may not meet contrast or semantics; tab order inside the Settings forms was not reviewed screen by screen; the chat rows' context menu and the window drag header are unchanged.

# MCP servers

Part of the [Gustaf documentation](../README.md).

Settings, MCP servers: connect [Model Context Protocol](https://modelcontextprotocol.io) servers and the agents of **API providers** (OpenAI, Anthropic, Gemini, OpenRouter, local models) can use their tools. **Claude Code, Codex and Cursor Agent use their own MCP configuration; Gustaf does not inject servers into them** (the list is not shared with them either).

- **Servers:** local servers over stdio (`command`, `args`, `env`, optional working directory; started from an argument array, never through a shell, with the login-shell `PATH`, so `npx`/`uvx` work) and remote servers over streamable HTTP (`url`, `headers`; JSON and SSE responses; `https://`, or `http://` to localhost) or the legacy HTTP+SSE transport. The server form has a **Transport** choice: automatic (default), streamable HTTP or legacy SSE. Automatic tries streamable HTTP first and switches to SSE when the initialize POST is rejected with a 4xx status other than 401, 403, 408 or 429 (those mean authorization, rate limiting or a timeout, not an old server; 5xx also never switches). Imported `type: "sse"` entries are set to legacy SSE. Each server is global or bound to one project, and can be disabled. Paste an `mcpServers` JSON block (Claude Desktop, Cursor, VS Code shape) with "Import JSON", or load `~/.cursor/mcp.json`.
- **Secrets:** env values and headers marked "Secret" (ticked automatically for names like `*_TOKEN`, `Authorization`) are stored in the macOS Keychain (`mcp:<server id>:env|header:<name>`), never in the settings database, and are removed with the server.
- **Lifecycle:** a stdio server starts on first use (or "Test connection"), does the `initialize` handshake, and is restarted with backoff if it crashes (at most 5 crashes in a row, then "Error" until started again). It is killed when disabled, edited, removed or when the app quits. Messages are capped (16 MB in, 4 MB out), every call has a timeout (60 s by default, per server), stderr goes to a bounded log shown under "Log". `notifications/tools/list_changed` refreshes the tool list.
- **In the agent:** tools are offered as `mcp__<server>__<tool>` (at most 64 characters, collisions get a numeric suffix) with their JSON Schemas sanitized and size-capped. Main agent only (subagents keep their fixed tool set). Results (text, one PNG image, resource links, embedded text resources) become tool results capped at 50,000 characters; other binary content is replaced by a note.
- **Approvals:** every call asks by default (Full access does not skip it). "Always allow" can be set per tool (also from the approval card) or per server. In read-only mode only tools you marked "Read-only" are offered and callable; hints from the server are shown but not trusted. Calls appear in the action log as `mcp__<server>__<tool>`. Tool output is untrusted data and the system prompt says so.

- **Cancellation:** stopping a run cancels the `tools/call` that is in flight. Stdio: the call returns at once and Rust sends `notifications/cancelled` with the request id and drops the pending entry, so an answer that still arrives is ignored. HTTP: the request is aborted, the client returns at once and posts `notifications/cancelled` (best effort); the server's late answer is never read. Timeouts send the same notification.
- **Resources:** a server that announces the `resources` capability gets built-in agent tools: `mcp__<server>__mcp_list_resources` (one line per resource), `mcp__<server>__mcp_read_resource` (`uri`, or a template with arguments, see below) and `mcp__<server>__mcp_list_resource_templates`. They follow the tool rules: every call asks unless allowed ("Always allow" and "Read-only" are set under the server's Tools, where they appear as built-in rows named `mcp_list_resources` / `mcp_read_resource` / `mcp_list_resource_templates`; in read-only mode only those marked read-only are offered). `resources/read` text is capped at 50,000 characters, one PNG up to 5 MB is attached, any other binary content is replaced by a note with its size. The resource list is cached until `notifications/resources/list_changed` (no subscriptions). Content is untrusted data.
- **Resource templates:** a server with `resources` also gets `mcp__<server>__mcp_list_resource_templates` (`resources/templates/list`, cached like the resource list; a server without the method has none), and `mcp_read_resource` accepts either `uri` or `template` (exactly as listed) plus `arguments` (strings). Templates are expanded as RFC 6570 level 1-2 (`{var}`, `{+var}`, `{#var}`); other syntax is shown as unsupported and cannot be read. The expansion is strict: every variable must be given and nothing else, values cannot contain control characters or `.`/`..` path segments (also percent-encoded once or twice), simple expansion percent-encodes everything but unreserved characters, a template must start with a literal scheme and cannot take a reserved expansion in its host part, and the expanded URI must keep the scheme and a literal host of the template. The approval card shows the template and arguments; "Always allow" and "Read-only" use the built-in name `mcp_list_resource_templates` (a third built-in row under Tools). A plain `uri` can still be any URI the server accepts.
- **Prompts:** the composer's attach menu has "MCP prompt…" when a server is configured. The dialog lists the prompts of enabled servers that announce `prompts` (global ones and those of this project), asks for the arguments, and only on "Insert" calls `prompts/get`; the rendered messages' text goes into the composer (a single user message as is, otherwise with User/Assistant prefixes, capped at 20,000 characters). Prompts are never offered to the model and nothing is sent automatically. `notifications/prompts/list_changed` refreshes the cached list.
- **OAuth (HTTP servers):** tick "Sign in with OAuth" in the server form (optional client ID and scope), then "Sign in" in the list. Flow per the MCP authorization spec (2025-06-18) with the 2025-03-26 fallback: an unauthenticated request gets the 401 challenge (`WWW-Authenticate: resource_metadata`; a legacy SSE server that answers the POST with a 4xx gets the GET probed for its challenge), then protected resource metadata (RFC 9728; its `resource` must cover the server URL), authorization server metadata (RFC 8414 and OpenID Connect locations; the `issuer` must match and `S256` PKCE must be advertised, otherwise sign-in is refused). **Servers without protected resource metadata** use their own origin as the issuer, so `/.well-known/oauth-authorization-server` there works (legacy metadata); and **only when every lookup on the origin was a clean 404** the default endpoints `/authorize`, `/token` and `/register` on the origin are used (2025-03-26). Metadata that is found but invalid is an error, never a reason to guess; lookups that fail in another way (5xx, timeout, junk, an unreadable document named by the challenge) end with `discovery_failed`, an authorization server named by the protected resource that publishes nothing with `no_metadata`, a failed registration at the default endpoint with `registration_failed` (the message says to enter a client ID). Then dynamic client registration (RFC 7591, public client) unless a client ID is configured, an authorization URL with `state`, `code_challenge` (S256) and `resource` (RFC 8707), opened in the system browser through the opener plugin. A Rust listener on `127.0.0.1:<random port>/callback` receives the redirect (state compared, Host checked, 5-minute timeout, cancelled by "Cancel"); the code is exchanged with the exact same redirect URI and the verifier. Every endpoint, default ones included, must be `https://` (http only for localhost). Tokens and the registered client live in the Keychain entry `mcp:<id>:oauth` (JSON), never in settings or logs; an `Authorization` header configured by hand is replaced by the OAuth token. The token is refreshed shortly before it expires and, once, after a 401 (one refresh at a time; `invalid_grant` deletes the tokens and asks to sign in again).
- **Sign-out and revocation:** if the authorization server metadata had a `revocation_endpoint` (RFC 7009; stored with the tokens, https only), "Sign out" first POSTs the refresh token and then the access token there (`token`, `token_type_hint`, `client_id`), each with a 5-second deadline, and then deletes the Keychain entry whatever the answer was: a failure, a timeout or a missing endpoint never blocks the local sign-out. Changing the URL or client ID, turning OAuth off or removing the server deletes the tokens the same way and revokes them in the background. Servers signed in before this version, and the default-endpoints path, have no stored revocation endpoint, so nothing is sent for them.
- **HTTP scope and OAuth:** discovery, registration, token and refresh requests go through the HTTP plugin, so they must be inside the `http:default` scope: `https://*` covers every https authorization server (also with a port) and loopback http covers a local one; the sign-in is stricter than the scope and refuses plain http authorization endpoints even for the private ranges the scope allows. Opening the browser uses `opener:allow-default-urls`, and the Rust listener is an app command. `tests/csp.test.mjs` checks the scope against representative OAuth endpoint URLs. See [security](security.md).

Not implemented: sampling, elicitation, roots (answered with an empty list), resource subscriptions, subagent access to MCP tools, CLI providers (own config). A legacy SSE connection has no session to end on the server and re-initializes after the stream drops; a request in flight when it drops fails (it is not replayed). The OAuth flow, the SSE transport and the template tools have only been exercised against fakes, not a real provider or MCP server, and nothing here was smoke-tested in `tauri dev`.

Logic: `src/agent/mcp/` (`config.ts`, `protocol.ts`, `toolset.ts`, `resources.ts`, `prompts.ts`, `oauth.ts`: pure; `oauthFlow.ts`: sign-in/refresh over injected dependencies; `http.ts`: streamable HTTP client over an injected `fetch`; `sse.ts`: legacy SSE client; `uriTemplate.ts`: RFC 6570 level 1-2 expansion; `runtime.ts`: settings, Keychain and connections), `src-tauri/src/mcp.rs` (stdio runtime), `src-tauri/src/oauth.rs` (loopback redirect listener), `components/McpServers.tsx` and `components/McpPromptDialog.tsx` (UI).

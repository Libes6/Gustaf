## Orchestrator (epic, 2026-10-03)

Goal: from "a chat with subagents" to an orchestrator that runs many agents of any provider in parallel, keeps their work mergeable and keeps the human review load manageable. Based on a comparison with Conductor, Cursor 3 Agents Window, Claude Code agent teams, Vibe Kanban, Mastra and research on agent merge conflicts (see the 2026-10-03 chat). Checked against the code on 2026-10-03: there is no git worktree support anywhere (isolation is the shadow copy in `review.rs`), `spawn_agent` / `delegate_tasks` run only on API providers, `Compare` is read-only, conflict handling is an overlap warning. Order: O1 → O2 → O3 are the foundation; O4–O7 build on them; O8–O10 later.

- [ ] **O1. Workspaces: one git worktree per task, any provider** (foundation; like Conductor / Cursor 3).
  - [ ] Rust `worktree.rs`: create `git worktree add <app data>/worktrees/<project-hash>/<task-id> -b gustaf/<slug>` from a chosen base (default: current branch head), list, remove (refuse with uncommitted changes unless confirmed), prune on start; never inside the project folder; non-git projects fall back to the shadow copy.
  - [ ] "New workspace" from the sidebar project menu and from the composer ("Run in new workspace"): picks provider/model, runs the project setup command (reuse shadow-copy setup + symlinked dependency dirs), the chat's cwd is the worktree. CLI providers (Codex, Claude Code, Cursor Agent) and API agents both work there.
  - [ ] Sidebar shows workspaces under the project with branch name, status badge (reuse `chatStatus.ts`), ahead/behind and changed-file count; "Open in terminal" (terminal pane cwd), "Reveal", "Archive" (removes the worktree, keeps the chat and branch).
  - [ ] Changes panel reads `git diff base...HEAD` + working tree of the worktree; commit / push / PR (`git_publish.rs`) work per workspace.
  - Acceptance: three workspaces in one repo run Codex, Claude Code and an API model at the same time, edit the same file differently, and the main checkout stays untouched; archive cleans up `git worktree list`. Tests: Rust worktree lifecycle on a temp repo (incl. dirty-worktree refusal), UI test for the sidebar group.
